## 1. 模块定位与工具箱全景

### 1.1 业务价值
在知识管理场景中，如果 Agent 仅具备“根据日记 ID 读取单篇内容”的粗粒度接口，模型将无法应对复杂的人类日常提问（如“我哪天去吃了烤肉？”、“我最近心情怎么样？”、“帮我整理关于工作复盘的记录”）。

**日记系统全套原生工具箱（Diary Toolset）** 是 Agent 感知并操作用户私有日记资产的“手”与“眼”。它为大模型赋予了全维度的日记资产掌控力：
- **宏观感知**：日记多维模糊过滤、历史情绪画像与打卡习惯大数据统计；
- **微观定位**：精准段落扫描、行号定位、上下文窗口抽取、单篇长文深度精读；
- **能动执行**：日记草稿自动起草入库、已有日记润色与尾部追加、带有安全二次确认的日记软删除。

## 2. 工具统一规范与类型定义（`types.ts`）

所有工具严格遵循 OpenAI API 标准的 **Function Calling / Tool Use** 规范，同时结合后端微内核的运行上下文：

```typescript
// Backend/src/core/agent/tools/types.ts

/**
 * OpenAI 格式的 JSON Schema 属性定义
 */
export interface JsonSchemaProperty {
  type: "string" | "number" | "integer" | "boolean" | "array" | "object";
  description: string;
  enum?: string[];
  items?: JsonSchemaProperty;
}

/**
 * 符合 OpenAI Tool 格式的定义
 */
export interface AgentToolDefinition {
  type: "function";
  function: {
    name: string;
    description: string;
    parameters: {
      type: "object";
      properties: Record<string, JsonSchemaProperty>;
      required?: string[];
    };
  };
}

/**
 * 工具执行上下文 (强制绑定当前安全认证用户)
 */
export interface AgentToolContext {
  userId: string;
  requestId: string;
  withdrawStack?: Array<() => Promise<void>>;
}

/**
 * 工具执行标准响应体
 */
export interface AgentToolResult<T = any> {
  success: boolean;
  data?: T;
  error?: string;
  summary: string; // 供前端打字机/胶囊卡片展示的简洁文案 (如: "已检索到 3 篇相关日记")
}

/**
 * 单个工具执行器函数签名
 */
export type AgentToolExecutor = (
  args: any,
  context: AgentToolContext
) => Promise<AgentToolResult>;
```

## 3. 七大原生日记工具详细设计与实现

### 3.1 工具一：`search_diaries`（多维度模糊/精确日记搜索）

- **功能定位**：帮助 Agent 在浩瀚的日记库中粗筛出符合主题、时间或特定心境的日记候选列表。
- **OpenAI 契约声明（JSON Schema）**：
  ```json
  {
    "name": "search_diaries",
    "description": "多维度检索用户的私有日记库。支持按关键词、起止日期、心情类型、天气特征进行组合筛选，返回匹配日记的基本摘要列表。",
    "parameters": {
      "type": "object",
      "properties": {
        "query": {
          "type": "string",
          "description": "搜索关键词，会在日记标题与正文中进行模糊匹配"
        },
        "startDate": {
          "type": "string",
          "description": "起始日期，格式 YYYY-MM-DD"
        },
        "endDate": {
          "type": "string",
          "description": "截止日期，格式 YYYY-MM-DD"
        },
        "mood": {
          "type": "string",
          "description": "心情筛选，如: Happy, Calm, Sad, Angry, Excited, Tired, Relaxed"
        },
        "weather": {
          "type": "string",
          "description": "天气筛选，如: Sunny, Cloudy, Rainy, Snowy, Windy"
        },
        "limit": {
          "type": "integer",
          "description": "返回最大结果数量，默认 10，最大上限 50"
        }
      }
    }
  }
  ```
- **核心执行逻辑与 SQL**：
  1. 组装参数化 SQL 查询条件，必须带上 `user_id = ? AND deleted_at IS NULL`；
  2. 若有 `query`，添加 `(title LIKE ? OR content LIKE ?)`，参数前后拼接 `%`；
  3. 若有 `startDate`，添加 `created_at >= ?`（拼上 `00:00:00`）；
  4. 若有 `endDate`，添加 `created_at <= ?`（拼上 `23:59:59`）；
  5. 若有 `mood` 或 `weather`，直接等值比对；
  6. 按照 `created_at DESC` 降序排列，截取 `LIMIT ?`；
  7. **正文摘要截断（150字）**：将正文去除多余 Markdown 标记后提取前 150 字符作为 `snippet`，统计 `charCount = content.length`，避免向大模型上下文灌入过长文本。
- **输出数据结构**：
  ```json
  {
    "totalMatches": 2,
    "diaries": [
      {
        "id": "7a8b9c-...",
        "title": "杭州西湖初秋漫步",
        "createdAt": "2026-09-12 16:30:00",
        "weather": "Sunny",
        "mood": "Relaxed",
        "isPublic": 1,
        "charCount": 1240,
        "snippet": "今天天气格外宜人，沿着苏堤一路走过去，荷叶已经开始泛黄，空气中有淡淡的桂花香味..."
      }
    ]
  }
  ```

### 3.2 工具二：`locate_diary_content`（段落级关键词精准定位与上下文抽取）

- **功能定位**：针对用户寻找具体事件细节的提问（如“我哪天提到了买Switch？”、“我和小明具体聊了什么？”），精准捕获命中的行号、所在语句与前后完整上下文片段。
- **OpenAI 契约声明（JSON Schema）**：
  ```json
  {
    "name": "locate_diary_content",
    "description": "精准扫描日记正文，提取包含关键词的具体段落、行号及前后 120 字符上下文切片。当用户回忆具体细节但不知道在具体哪篇日记时极其有用。",
    "parameters": {
      "type": "object",
      "properties": {
        "keyword": {
          "type": "string",
          "description": "必须提供的定位关键词或短语"
        },
        "diaryId": {
          "type": "string",
          "description": "可选的日记 ID。若指定则仅在该篇日记内定位，若不指定则全局扫描该用户的所有未删除日记"
        },
        "maxMatches": {
          "type": "integer",
          "description": "最大返回匹配片段数，默认 5，最大 20"
        }
      },
      "required": ["keyword"]
    }
  }
  ```
- **核心算法设计**：
  1. 针对全量或指定日记拉取 `{ id, title, content, created_at }`；
  2. 遍历日记正文，按换行符 `\n` 切分为行数组：
     - 记录行号 `lineNumber`（1-indexed）；
     - 扫描每行是否包含 `keyword`；
     - 命中时，计算该关键词在整篇文本中的绝对偏移量 `matchOffset`；
     - 截取关键词前方 120 个字符与后方 120 个字符，构建 `contextSnippet`；
     - 在切片内用显著标记（如 `【关键词】`）包裹目标词；
  3. 统计命中频次，按照匹配时间倒序聚合；
  4. 达到 `maxMatches` 时自动截断并返回。
- **输出数据结构**：
  ```json
  {
    "keyword": "烤肉",
    "matchedCount": 1,
    "locations": [
      {
        "diaryId": "d-123456",
        "diaryTitle": "周末聚餐与复盘",
        "createdAt": "2026-08-15 20:00:00",
        "lineNumber": 24,
        "lineText": "晚上和张三李四一起去吃了日式烤肉，聊到了下半年的计划。",
        "contextSnippet": "...下午看完了两篇架构论文，收获很大。晚上和张三李四一起去吃了日式【烤肉】，聊到了下半年的计划。大家都觉得现在的微内核方向非常对..."
      }
    ]
  }
  ```

### 3.3 工具三：`read_diary_detail`（日记全文深度精读）

- **功能定位**：通过日记 ID 读取单篇日记的完整 Markdown 正文与全量元数据，供 Agent 进行深度总结、提炼要点、情感共鸣或文章扩写。
- **OpenAI 契约声明（JSON Schema）**：
  ```json
  {
    "name": "read_diary_detail",
    "description": "根据日记 ID 深度读取单篇日记的完整 Markdown 内容、天气、心情、创建时间与公开状态。用于长文分析、提炼总结或文本润色。",
    "parameters": {
      "type": "object",
      "properties": {
        "diaryId": {
          "type": "string",
          "description": "目标日记的唯一 ID"
        }
      },
      "required": ["diaryId"]
    }
  }
  ```
- **核心执行逻辑**：
  1. 先行尝试从微内核内存缓存 `MemoryCache.getKV("diaries", diaryId)` 命中数据；
  2. 若未命中，执行 `SELECT id, user_id, title, content, weather, mood, is_public, created_at, updated_at, deleted_at FROM diaries WHERE id = ? LIMIT 1`；
  3. **严格多租户校验**：核验 `row.user_id === context.userId` 且 `row.deleted_at === null`，若不匹配立即返回错误：“日记不存在或无权访问”；
  4. 回填至内存缓存 `MemoryCache.setKV("diaries", diaryId, row)`；
  5. 返回完整对象。
- **输出数据结构**：
  ```json
  {
    "id": "d-123456",
    "title": "周末聚餐与复盘",
    "content": "# 周末聚餐与复盘\n\n下午看完了两篇架构论文...",
    "weather": "Sunny",
    "mood": "Happy",
    "isPublic": 1,
    "createdAt": "2026-08-15 20:00:00",
    "updatedAt": "2026-08-15 22:30:10",
    "charCount": 2180
  }
  ```

### 3.4 工具四：`get_diary_timeline_stats`（日记生命周期与心理画像统计）

- **功能定位**：跨时空汇总统计用户的创作轨迹与情绪晴雨表，让 Agent 化身为用户的私人数据分析师。
- **OpenAI 契约声明（JSON Schema）**：
  ```json
  {
    "name": "get_diary_timeline_stats",
    "description": "聚合统计用户的日记生命周期数据。包含篇数总计、字数统计、心情频次与心理晴雨表分布、天气占比以及高频创作时段。",
    "parameters": {
      "type": "object",
      "properties": {
        "timeRange": {
          "type": "string",
          "enum": ["all", "this_week", "this_month", "recent_30_days", "this_year"],
          "description": "时间跨度范围，默认为 all (全量历史)"
        }
      }
    }
  }
  ```
- **核心 SQL 聚合算法**：
  1. 计算 `timeRange` 对应的 SQL 起止条件：
     - `this_week`：`created_at >= DATE_SUB(CURDATE(), INTERVAL WEEKDAY(CURDATE()) DAY)`
     - `this_month`：`created_at >= DATE_FORMAT(CURDATE(), '%Y-%m-01')`
     - `recent_30_days`：`created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)`
     - `this_year`：`created_at >= DATE_FORMAT(CURDATE(), '%Y-01-01')`
  2. 并行执行多维聚合统计：
     - **总量聚合**：`SELECT COUNT(*) as totalNotes, SUM(CHAR_LENGTH(content)) as totalChars, AVG(CHAR_LENGTH(content)) as avgChars, MIN(created_at) as firstNoteAt, MAX(created_at) as lastNoteAt FROM diaries WHERE ...`
     - **心情画像**：`SELECT mood, COUNT(*) as count FROM diaries WHERE ... GROUP BY mood ORDER BY count DESC`
     - **天气分布**：`SELECT weather, COUNT(*) as count FROM diaries WHERE ... GROUP BY weather ORDER BY count DESC`
     - **高频创作时段**：`SELECT HOUR(created_at) as writeHour, COUNT(*) as count FROM diaries WHERE ... GROUP BY writeHour`（归类为清晨 5-9点、日间 9-18点、晚间 18-23点、深夜 23-5点）
  3. 计算各心情的占比百分比（如 Happy 45.2%）。
- **输出数据结构**：
  ```json
  {
    "timeRange": "recent_30_days",
    "summary": {
      "totalNotes": 18,
      "totalChars": 24500,
      "avgChars": 1361,
      "earliest": "2026-08-19 09:12:00",
      "latest": "2026-09-17 22:45:00"
    },
    "moodDistribution": [
      { "mood": "Happy", "count": 8, "percentage": "44.4%" },
      { "mood": "Calm", "count": 6, "percentage": "33.3%" },
      { "mood": "Tired", "count": 4, "percentage": "22.2%" }
    ],
    "peakWritingPeriod": "晚间 (18:00 - 23:00) 占 65%",
    "dominantMood": "Happy (积极充实)"
  }
  ```

### 3.6 工具六：`update_diary`（日记润色、修正与追加）

- **功能定位**：对已有日记进行文字润色、错误修正或在文末自动追加总结，具备细粒度行级锁保护。
- **OpenAI 契约声明（JSON Schema）**：
  ```json
  {
    "name": "update_diary",
    "description": "对用户已有的指定日记进行内容更新、润色或在文末追加内容。具备并发行锁与数据回滚保护。",
    "parameters": {
      "type": "object",
      "properties": {
        "diaryId": {
          "type": "string",
          "description": "要更新的目标日记 ID"
        },
        "title": {
          "type": "string",
          "description": "可选的新标题，若不提供则保留原标题"
        },
        "content": {
          "type": "string",
          "description": "可选的全量新正文。若提供则全量覆盖旧正文"
        },
        "appendContent": {
          "type": "string",
          "description": "可选的文末追加内容。若提供将在现有正文末尾空两行后自动追加"
        },
        "weather": {
          "type": "string",
          "description": "可选的新天气"
        },
        "mood": {
          "type": "string",
          "description": "可选的新心情"
        }
      },
      "required": ["diaryId"]
    }
  }
  ```
- **核心并发与事务保护算法**：
  1. **申请行级并发排他锁**：
     ```typescript
     const lockRes = await RowLockManager.acquireRowLock("diaries", diaryId, "UPDATE", context.requestId);
     if (lockRes.status === 0) return { success: false, error: `并发更新冲突: ${lockRes.content}`, summary: "更新失败" };
     ```
  2. **提取旧行快照（Snapshot）**：
     执行 `SELECT * FROM diaries WHERE id = ? AND user_id = ? AND deleted_at IS NULL`；若记录不存在立即释放锁并返回错误；
  3. **计算新内容**：
     - 若提供了 `appendContent`，则 `finalContent = oldRow.content ? `${oldRow.content}\n\n${appendContent}` : appendContent`；
     - 若提供了 `content`，则使用新 `content`；
  4. **执行 UPDATE**：
     `UPDATE diaries SET title = ?, content = ?, weather = ?, mood = ?, updated_at = NOW() WHERE id = ?`；
  5. **注册 Saga 逆向补偿闭包**：
     将回滚到 `oldRow` 的 SQL 与缓存还原逻辑推入 `context.withdrawStack`；
  6. **驱逐脏缓存**：`MemoryCache.delKV("diaries", diaryId)`；
  7. **释放行锁**：`RowLockManager.releaseRowLock("diaries", diaryId, context.requestId, true)`；
  8. 返回更新成功结果。
- **输出数据结构**：
  ```json
  {
    "success": true,
    "diaryId": "d-123456",
    "updatedFields": ["content", "updatedAt"],
    "newCharCount": 1620,
    "message": "日记已完成更新并追加内容"
  }
  ```

### 3.7 工具七：`delete_diary`（删除日记）

- **功能定位**：在用户明确下达删除指令后执行软删除。
- **安全红线机制（Safety Guardrail）**：
  - 删除具有不可逆的破坏性。大模型有时会过度解读用户意图（例如用户说“这篇日记写得太烂了”，模型不应擅自执行删除）；
  - 因此强制要求参数必须带有 `confirmed: true`。若模型未携带或为 `false`，工具内部主动拒绝并返回拦截提示，指导模型向用户发起二阶段明确询问。
- **OpenAI 契约声明（JSON Schema）**：
  ```json
  {
    "name": "delete_diary",
    "description": "删除指定的日记。属于不可逆的破坏性操作，强制要求用户已明确给出删除指示且参数 confirmed 必须为 true。",
    "parameters": {
      "type": "object",
      "properties": {
        "diaryId": {
          "type": "string",
          "description": "要删除的日记 ID"
        },
        "confirmed": {
          "type": "boolean",
          "description": "是否已获得用户明确的二次确认指令。必须为 true 才会执行真实删除"
        }
      },
      "required": ["diaryId", "confirmed"]
    }
  }
  ```
- **核心执行逻辑**：
  1. 检查 `confirmed === true`。若不为 `true`：
     ```typescript
     return {
       success: false,
       error: "SAFETY_CONFIRMATION_REQUIRED",
       summary: "需要用户二次确认",
       data: {
         message: "⚠️ 警告：删除日记属于破坏性操作。请向用户明确确认：‘确认要永久删除这篇日记《xxx》吗？’，待用户肯定答复后再带 confirmed: true 重新调用。"
       }
     };
     ```
  2. 核验日记归属权 `user_id === context.userId`；
  3. 执行软删除：`UPDATE diaries SET deleted_at = NOW() WHERE id = ? AND user_id = ?`；
  4. 驱逐缓存：`MemoryCache.delKV("diaries", diaryId)`；
  5. 压入撤销恢复闭包（若本轮后续操作异常可回退）；
  6. 返回删除成功提示。

## 4. 工具注册中心设计（`src/core/agent/tools/index.ts`）

为了实现低耦合、高扩展的工具管理体系，建立统一的工具注册中心：

```typescript
// Backend/src/core/agent/tools/index.ts

import { AgentToolDefinition, AgentToolContext, AgentToolResult, AgentToolExecutor } from "./types.js";
import { diaryTools, diaryExecutors } from "./diaryTools.js";
import { webSearchTool, webSearchExecutor } from "./webSearchTool.js"; // 模块三待接入

class AgentToolRegistry {
  private definitions: Map<string, AgentToolDefinition> = new Map();
  private executors: Map<string, AgentToolExecutor> = new Map();

  constructor() {
    this.registerAll();
  }

  private registerAll() {
    // 注册日记原生 7 大工具
    for (const def of diaryTools) {
      this.definitions.set(def.function.name, def);
    }
    for (const [name, fn] of Object.entries(diaryExecutors)) {
      this.executors.set(name, fn);
    }

    // 预留注册外部工具 (如 web_search)
    this.definitions.set(webSearchTool.function.name, webSearchTool);
    this.executors.set(webSearchTool.function.name, webSearchExecutor);
  }

  /**
   * 导出供 OpenAI Chat Completions 接口使用的 tools 数组
   */
  public getOpenAiTools(): AgentToolDefinition[] {
    return Array.from(this.definitions.values());
  }

  /**
   * 分发并执行工具调用
   */
  public async executeTool(
    toolName: string,
    argsStringOrObj: string | any,
    context: AgentToolContext
  ): Promise<AgentToolResult> {
    const executor = this.executors.get(toolName);
    if (!executor) {
      return {
        success: false,
        error: `未知工具调用: [${toolName}]`,
        summary: `工具 [${toolName}] 不存在`,
      };
    }

    let parsedArgs: any = {};
    if (typeof argsStringOrObj === "string") {
      try {
        parsedArgs = JSON.parse(argsStringOrObj);
      } catch (err: any) {
        return {
          success: false,
          error: `工具入参 JSON 解析失败: ${err.message}`,
          summary: "参数解析异常",
        };
      }
    } else {
      parsedArgs = argsStringOrObj || {};
    }

    try {
      return await executor(parsedArgs, context);
    } catch (err: any) {
      return {
        success: false,
        error: `工具执行异常: ${err.message || String(err)}`,
        summary: `执行 [${toolName}] 失败`,
      };
    }
  }
}

export const ToolRegistry = new AgentToolRegistry();
```

## 5. 多租户安全沙箱与并发控制保障

### 5.1 数据隔离红线
所有数据查询与更新，工具层统一通过 `context.userId` 注入，杜绝以下安全漏洞：
1. **水平越权（IDOR）**：即使模型传入了其他用户的 `diaryId`，SQL 层面的 `WHERE id = ? AND user_id = ?` 将使其自动落空，确保用户数据严格私有；
2. **SQL 注入拦截**：严格使用 MySQL2 连接池的参数化查询（`?` 占位符），禁止直接拼接 SQL 字符串；
3. **软删除感知**：所有查询默认带上 `deleted_at IS NULL`，避免模型读取已废弃的历史数据。

### 5.2 并发行锁与 Saga 回滚保护
在 `update_diary` 等写操作中，引入微内核现有的 [`RowLockManager`](file:///d:/Projects/DiarySystem/Backend/src/core/lock/rowLockManager.ts)：
- 在更新前获取行锁，防止同一用户的多次并发提问或多端写入产生脏写覆盖；
- 失败时通过 `withdrawStack` LIFO 逆序自动撤销，保障数据一致性。
