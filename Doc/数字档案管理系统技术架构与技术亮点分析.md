# 数字档案管理系统（Digi-Archive）技术架构与技术亮点深度分析

---

## 1. 项目概述与系统定位

### 1.1 项目背景
本系统为大三上学期末自主设计并研发的企业级**数字档案管理系统（Digital Archive Management System，代码仓标识 `digi-archive`）**。系统围绕企事业单位档案全生命周期的规范化、数字化与流程化管理需求构建，覆盖档案的**收集著录、预归档审核、编目归档、多模式检索、借阅申请审批、全宗/部门维护、细粒度 RBAC 权限控制以及防误删回收站机制**。

### 1.2 核心技术栈
- **核心框架**：Vue 3 (`<script setup>` Composition API 组合式语法)
- **工程构建与热更**：Vite（基于原生 ESM 模块化的高速构建工具）
- **基础组件库**：Element Plus（桌面端规范组件库）
- **状态管理中枢**：Pinia（轻量化响应式状态树）
- **前端路由**：Vue Router 4
- **网络通信与接口流控**：Axios（深度定制统一请求中间件、Mock 拦截与引用计数式加载反馈）
- **度量与渲染引擎**：HTML5 Canvas 2D Context（用于文本像素宽度实时精准度量）、DOMParser（用于 SVG 矢量图形内联解析注入）

## 2. 整体架构设计与核心运行机制

不同于传统后台系统“一个路由对应一个写死的 Vue 页面”这种容易导致冗余与难以维护的模式，该系统从底层确立了**「配置驱动视图（Schema-Driven UI） + 核心宿主容器 + 自研原子组件」**的抽象分层架构。

### 2.1 多任务保活工作台机制 (`main.vue`)
- **多标签页（Multi-Tab）并行操作**：系统借鉴了专业桌面应用的操作习惯，在顶部设计了多标签导航栏。用户可以同时开启“档案著录”、“档案检索”、“部门管理”等多个任务。
- **状态不丢失保活**：Tab 切换采用内部状态数组 `openedPages` 与 `v-show` 条件渲染，避免了频繁切换时页面的反复销毁与重建。用户录入到一半的未提交表单、检索结果的分页与勾选状态均能完整保留。
- **标签页关闭与联动解耦**：通过全局事件总线 `tool.event.onChange('closeMainPage', ...)`，支持子页面在完成某项流转（如归档成功）后，向父级发送信号安全关闭当前 Tab 并平滑激活相邻 Tab。

### 2.2 统一动态页面宿主 (`content.vue`)
全站十多个核心业务模块均由同一个通用宿主组件 `content.vue` 承载：
1. 宿主组件根据传入的 `url` 参数，动态索引对应的业务配置函数（如 `content['archive-search']`）；
2. 业务配置函数以闭包形式执行，返回一个异步的页面构造器（Page Constructor）；
3. 宿主组件解析返回的数据结构，自适应渲染为包含**「左侧分类树 + 顶部操作条 + 核心数据区（单/双层 Tab 表格/列表/表单）」**的高内聚界面。

## 3. 核心技术亮点深度剖析

### 亮点一：纯自研零占位滚动与自适应测宽数据表格 (`cDataTable.vue`)

针对数据密集型表格在传统实现中常见的“内容被滚动条挤压抖动”以及“列宽固定截断或布局失衡”两大痛点，项目自研了专门的数据表格组件 `cDataTable.vue`。

#### 1. 零占位无感滚动条设计（Anti-Layout-Shift）
- **现象分析**：在桌面端（尤其 Windows/Chrome/Edge 环境）下，原生滚动条会出现 6px~17px 的物理占位。当列表数据从少变多出现垂直滚动条时，会突然将内容区向内挤压，导致表格各列宽度瞬间跳变，排版发生明显的横向跳动（Layout Shift）。
- **工程解法**：`cDataTable` 抛弃了原生表格标签，采用扁平的 `div` 绝对与相对定位布局，结合 `.hideScrollbar` 体系：
  ```css
  /* 屏蔽平台滚动条的物理空间占用，保留原生滚轮与触控滑动能力 */
  scrollbar-width: none !important;
  -ms-overflow-style: none !important;
  *::-webkit-scrollbar {
    display: none !important;
    width: 0 !important;
    height: 0 !important;
  }
  ```
  表头与表体通过独立的图层与相同的宽度计算函数进行渲染，即便纵向数据超过千行出现滚动，整个表格容器的视口宽度也维持 100% 绝对恒定，彻底消除了排版挤压。

#### 2. 基于 Canvas 2D `measureText` 的毫秒级列宽自适应算法
传统开发通常采用硬编码宽度（如 `width: 150`），或者依赖浏览器的 `table-layout: auto`（这会在数据量大时引发沉重的回流重排计算）。

`cDataTable` 创新性地引入了基于离屏 Canvas 的字符几何度量算法：
```javascript
// tool.js
getTextWidth(text, fontSizePx, fontFamily = 'Arial') {
    try {
        if (typeof(text) !== 'string') text = this.JSON.stringify(text);
    } catch (error) {
        text = `${text}`;
    }
    const canvas = document.createElement('canvas');
    const context = canvas.getContext('2d');
    context.font = `${fontSizePx}px ${fontFamily}`;
    return Number(context.measureText(text).width);
}
```
在表格初始化与数据更新时，组件遍历每个字段及其首屏全部单元格内容：
```javascript
// cDataTable.vue
form.forEach(element => {
    // 首先度量表头标题文本的物理像素宽度
    let maxWidth = tool.getTextWidth(element.title, '14px') * this.multipleWidth + this.spareWidth;
    // 遍历数据行，寻找该列内容最大宽度
    list.forEach(item => {
        let currentWidth = tool.getTextWidth(item[element.field], '14px') * this.multipleWidth + this.spareWidth;
        if (currentWidth > maxWidth) {
            maxWidth = currentWidth;
        }
    });
    // 固化为该列的最佳初始像素宽度
    this.columnWidth[element.field] = {
        default: maxWidth,
        current: maxWidth
    };
});
```
- **算法优势**：
  - 计算完全在纯 JavaScript 内存中完成，耗时仅几毫秒，不触发布局树的重排（Reflow）；
  - 既能保证短文字（如“年度”、“状态”）不会被分配过宽的空间，又能保证长字符（如“档号”、“题名”）完整展示无不必要省略。

#### 3. 交互式列宽自由缩放（Column Drag-to-Resize）
每列分隔线处挂载微型拖拽控柄，结合全局鼠标坐标监听：
- 拖拽过程中实时计算偏移差值：`currentWidth += (e.x - lastX)`；
- 设立最小安全防护阈值：当宽度小于 30px 时进行拦截，防止列被拖至负宽度导致布局崩溃；
- 释放鼠标时触发 `mouseUp` 状态同步，保证了接近专业桌面软件的交互手感。

#### 4. 操作列自适应与状态管理
- 操作列宽度根据每一行配置的具体功能项数量动态计算（`maxOperationNum * opWidth + opSpare`）；
- 单双行交替斑马纹配色（`line` 与 `line2`）；
- 结合多选状态机呈现鲜明的选中背景（微软蓝 `#0078d4`），高亮的同时自动适配文字与反选图标。

### 亮点二：声明式 Low-Code 页面协议与通用组件体系

在 `src/contents/` 目录下的 11 个核心业务文件中，没有出现重复冗余的 `<template>` 视图代码，所有业务页面均以统一的声明式规范（`content格式`）进行书写。

#### 1. 规范化对象结构
每个业务模块仅需导出一个闭包函数，返回如下规范对象：

        title: '档案门类',
        list: leftCategoryData,
        props: { children: 'children', label: 'name' },
        callBack: async (node) => { /* 节点点击联动 */ }

    main: {                        // 右侧核心主工作区
        title: '档案检索',
        controls: [ /* 顶部全局工具条 */ ],
        tab: [                     // 支持单层或案卷/卷内双层 Tab
            {
                title: '案卷',
                topControls: [ ... ],    // 上工具条（搜索框、按钮组、快捷分类）
                data: {                  // 数据实体：可声明为 table、list 或 form

                    form: columnConfig,
                    list: tableData,

#### 2. 工具栏声明式构造器（`cControls.vue`）
`cControls` 组件是一个轻量且功能完备的操作栏解析器：
- 支持 `button`（常规/朴素/圆角按钮与左右图标支持）、`input`（回车即触发的搜索输入框）、`select` / `select2` / `groupSelect`（分组下拉选择）、`link`、`label` 等丰富控件类型；
- 在 `tool.cControls` 中封装了工厂方法，业务开发只需调用一行 `tool.cControls.pageSizeControls(...)`，即可自动生成包含**「总数统计、首尾页跳转、动态滑动窗口页码按钮、指定页码输入直达、每页条数切换下拉、即时刷新」**的全功能分页栏，大幅降低了模板代码编写量。

#### 3. 案卷与卷内上下双层 Tab 的伸缩折叠（`cTab.vue`）
- 档案系统特有的业务场景是“案卷”与“卷内文件”通常需要同屏对比查看；
- `content.vue` 结合 `cTab.vue` 支持上下双层面板；
- 面板中间设计了水平分割条（Splitter），支持按住鼠标上下拖动调节比例；
- 每个面板右侧均提供折叠控柄，点击即可瞬间收拢为 26px 的极简标题栏，将全部可用空间让渡给另一方。

### 亮点三：智能表单渲染与自动规则计算引擎 (`cForm.vue` & `tool.autoGenValue`)

档案业务涉及的录入字段极多（单门类常包含数十至上百项元数据）。为此系统专门打造了通用表单组件 `cForm.vue`。

#### 1. 表单内全字段即时搜索与统计
- 面对庞大的档案著录表单，用户查找特定字段极其费时。`cForm` 在表单顶部嵌入了即时过滤搜索框：
  - 支持对**「字段名称」**与**「字段当前值」**进行双向模糊检索；
  - 顶部利用 `position: sticky` 与 `backdrop-filter: blur(40px)` 毛玻璃设计了吸顶提示条；
  - 动态统计并展示命中情况，如：`字段名称包含“全宗”（3个/48个）`。

#### 2. 文本精准高亮与内容选中保护（`tool.getStringHighlightedHTML`）
在检索匹配时，常见实现如果直接用 `replace` 替换 HTML，容易破坏 DOM 结构或在用户用鼠标选中文本复制时把隐藏样式标签带出来。
系统自研了基于索引定位的切片高亮算法：
- 识别目标子串在长字符串中的所有非重叠偏移量；
- 对命中的字符片段包裹专用样式标签，未命中部分保持原样；
- 为高亮标签统一添加 `user-select: text` 样式，保证搜索高亮呈现的同时，用户自由选中文本复制体验不受任何干扰。

#### 3. 动态字段规则自动计算生成器（`builders`）
- **业务痛点**：档案行业有严格的编目规范，档号通常是由多个前置字段拼接而成的复合编码（例如：`档号 = 全宗号 - 分类号 - 年度 - 保管期限 - 件号`）。如果由人工重复敲打，不仅效率低下而且极易出错。
- **技术实现**：`cForm` 接收 `builders` 规则映射，并在组件内部深度监听表单数据流：
  ```javascript
  watch(() => value, () => {
      if (props.builders) {
          for (let i = 0; i < Object.keys(props.builders).length; i++) {
              const targetField = Object.keys(props.builders)[i];
              // 根据配置的依赖字段和分隔符，自动抽取当前最新值拼装复合内容
              value.value[targetField] = tool.autoGenValue(
                  props.builders[targetField], 
                  value.value
              );
          }
      }
      emit('change', value.value);
  }, { deep: true });
  ```
  录入人员在修改年度或保管期限时，档号输入框会即刻以毫秒级自动重组出合规的完整档号，从源头上保障了档案数据的规范性。

#### 4. 只读态（ReadMode）与编辑态的同构设计
同一份表单配置可接收 `readMode: Boolean` 属性：
- 编辑态下渲染为输入框、下拉框、日期时间选择器等控件；
- 只读态下自动转换为紧凑排版的图文数据展示，对日期类型调用 `tool.formatDate3` 规范格式化，对下拉选项匹配显示其可读的中文 `title`，实现了一套配置两处复用。

### 亮点四：轻量级无痕撤销与快照回滚状态机 (`DataRecovery.js`)

在诸如角色权限配置、批量修改状态等高敏感操作中，常规做法是在操作失败时从后端重新拉取全量列表。而在网络延迟较高或离线场景下，这种重新请求会导致明显的界面闪烁与停顿。

系统自研了一套基于快照栈（Snapshot Stack）的轻量化无痕状态撤销机制：
```javascript
// dataRecovery.js
class DataRecovery {
    constructor(recordData = () => { }, recoveryData = (data) => { }) {
        this._recordData = () => recordData();
        this._recoveryData = recoveryData;
    }
    dataHistory = [];
    
    // 拍摄快照并入栈，返回该次快照唯一编号
    record() {
        let id = this.dataHistory.length ? this.dataHistory[this.dataHistory.length - 1].id + 1 : 1;
        this.dataHistory.push({
            id,
            data: JSON.stringify(this._recordData())
        });
        return id;
    }
    
    // 恢复至指定编号的快照状态
    recovery(id) {
        for (let i = 0; i < this.dataHistory.length; i++) {
            if (this.dataHistory[i].id == id) {
                this._recoveryData(JSON.parse(this.dataHistory[i].data));
                return;
            }
        }
    }
}
```

#### 实战应用场景
在 `permission-management.js`（权限管理）中，当用户调整角色权限并提交时：
```javascript
// 1. 操作前捕获状态快照
let dataRCD = roleDataMgr.record();

// 2. 使用统一流控函数执行
tool.flow(async () => {
    // 乐观变更本地数据并向后端同步
    ...
    await this.submit();
    tool.toast.success('保存成功');
}, (err) => {
    // 3. 一旦异步过程出现任何网络中断或校验失败，毫秒级原子回滚至操作前状态
    tool.toast.error(`${err}`);
    roleDataMgr.recovery(dataRCD);
});
```
这种模式既实现了界面的极速响应（无需等待重拉全表），又在发生异常时能瞬时复原，具备极高的鲁棒性。

### 亮点五：全站三维视口拖拽调节与持久化记忆系统

系统界面包含三处核心分割区域：
1. **系统左侧一级主菜单**的展开宽度；
2. **业务页面左侧门类/组织机构树**的宽度；
3. **主工作区上下双层 Tab**（案卷 vs 卷内）的高度。

#### 1. 全局鼠标坐标中枢设计
传统拖拽实现如果分散在各个子组件中分别绑定 `mousemove`，当鼠标移动过快脱离组件区域时极易发生“脱轨”或事件丢失。

本系统在最外层根组件 `App.vue` 建立了全局鼠标坐标跟踪体系：
```vue
<!-- App.vue -->
<div 
  @mouseup="() => tool.event.setItem('globalMouseUp', store.mousePosition)"
  @mousemove="(e) => store.updateMousePosition({ x: e.x, y: e.y })"
>
  <router-view></router-view>
</div>
```
- 任意组件发起拖拽时，只需将内部的 `resizing` 标志置为 `true`，并利用 `watch(() => store.mousePosition)` 接收全局坐标差值进行物理伸缩；
- 当在窗口任意位置松开鼠标时，顶层触发 `globalMouseUp`，拖拽立即平滑终止，杜绝任何卡死或拖拽事件丢失。

#### 2. 本地偏好记忆持久化（`tool.resize`）
在用户调整好理想的宽度和高度后，系统自动通过 `localStorage` 写入键值：
- `leftMenuWidth`：主菜单宽度（默认 `240px`）
- `mainType1LeftTreeWidth`：左侧分类树宽度（默认 `310px`）
- `mainType1ContentTabHeight`：双层 Tab 高度分配（默认 `400px`）

用户在刷新网页或下次重新登录时，系统自动读取历史偏好初始化布局尺寸，保障了良好的工位定制体验。

### 亮点六：跨分页多选状态机（`mSelectObject` / `mSelectControls`）

在传统基于表格自带的多选实现中，用户点击分页切换到第 2 页后，第 1 页所勾选的数据往往直接被底层组件清空丢失，导致无法实现跨多页批量归档、批量导出或批量删除。

#### 1. 独立的选区状态集合管理
系统在 `tool.cControls.mSelectObject` 中实现了一个独立于当前表格视图生命周期的选区管理对象：
- 使用基于 Set 的去重模型维护选中的 ID 集合（`add`、`remove`、`is`、`removeAll`）；
- 跨越分页操作时，不论当前处于第几页，历史勾选的记录 ID 始终在内存集合中稳固保存。

#### 2. 自动化批量操作控件流
调用 `tool.cControls.mSelectControls` 可以自动装配出一套逻辑自洽的操作组：
- 实时呈现 **「已选 X 个」** 的高亮统计徽章；
- 智能感知当前页状态，动态输出 **「当前页全选」** 与 **「当前页全反选」**；
- 当有选区存在时，自动追加 **「取消多选」** 按钮以及外部注册的批量业务功能（如“批量打印”、“批量导出”、“批量移交”）。

### 亮点七：高内聚全局基础设施与工程化小而美设计

#### 1. 30 行轻量解耦的响应式事件总线 (`event.js`)
项目没有盲目引入庞大的第三方事件总线库，而是用原生闭包手写了一个仅 30 余行的轻量 Pub/Sub 模块：
- 支持 `setItem`、`getItem`、`removeItem` 和 `onChange` 监听；
- 成功解耦了诸如全局加载蒙版显示/隐藏（`controlLoadingMask`）、全局鼠标释放（`globalMouseUp`）以及跨组件页面关闭请求（`closeMainPage`）等全局异步通知。

#### 2. 引用计数式防闪烁全局加载遮罩 (`tool.loading`)
在复杂页面初始化时，往往会并发发起 3~4 个异步请求（如查门类、查字典、查首屏列表）。如果每个请求单独开关 Loading，会导致加载蒙版频繁闪烁：
```javascript
loading: {
    c: 0,
    show() {
        to.event.setItem('controlLoadingMask', true);
        this.c++; // 计数器累加
    },
    async hide() {
        this.c--; // 计数器递减
        if (!this.c) { // 仅当全部并发请求均已完成时才关闭蒙版
            to.event.setItem('controlLoadingMask', false);
        }
    }
}
```
结合全局带亚克力毛玻璃滤镜（`backdrop-filter: blur(10px)`）与半透明阴影的极简动画圈，界面加载过渡平稳无视觉杂音。

#### 3. 本地全真离线 Mock 拦截引擎 (`requestFakeData.js`)
在系统模块 `tool.requestData` 内部集成了本地 Mock 探测器：
- 支持按接口名称独立配置 Mock 开关与模拟数据集；
- 当服务端接口尚未就绪或处于无后端演示环境时，系统自动模拟 0.5 秒的网络传输时延后返回结构化假数据；
- 确保系统在无任何服务端支撑的环境下，也能完成完整的功能演示与前端界面测试。

#### 4. 基于 Vite Glob 动态导入的 SVG 矢量图标内联组件 (`cIcon.vue`)
传统前端使用图标要么打包庞大的字体图标库（如 FontAwesome、Iconfont），要么引入复杂的 SVG Sprite 生成插件。
`cIcon.vue` 巧妙利用了 Vite 的构建期元功能：
```javascript
const svgPaths = import.meta.glob('/src/assets/*.svg', { as: 'raw' });
```
- 组件在运行时根据传入的 `name` 属性（如 `name="delete"`），按需提取对应的原始 SVG 文本；
- 通过浏览器原生 `DOMParser` 解析后内联填入 `<svg fill="currentColor">` 中；
- 既享有纯矢量图形无损缩放、色彩随父级文本颜色（`color`）自动变换的灵活性，又避免了将全量图标打入主包的体积开销。

## 5. 工程思考、设计权衡与演进建议

在复盘大三时期完成的该套架构实现时，既能清晰地看到其在**工程化抽象、通用组件复用、性能微优化**等维度的出彩亮点，也可以从现代前沿前端架构视角客观审视其中的设计权衡与演进空间：

### 5.1 纯前端 Schema 驱动的灵活性权衡
- **优势**：所有业务逻辑聚合在单个 JS 文件内，开发一个全新的管理模块仅需书写数据声明，开发效率极高。
- **权衡**：当某个复杂业务模块出现高度特化的非标准 UI（例如带图表的统计大屏或自由看板）时，纯声明式对象结构需要扩展新的控件解析规则。在大型企业项目中，可考虑在 `cControls` 与 `cTab` 体系中增加具名插槽（Scoped Slots）机制，为特异性极强的定制区域预留原生 Vue 组件的插入入口。

### 5.2 状态管理与代码规范演进
- **现状**：项目使用了 47KB 的超大工具集 `tool.js`，内部集成了数组、对象、字符串、DOM、日期、画布度量等丰富算法。
- **优化路径**：
  - 可将 `tool.js` 按照功能域拆分为小而独立的实用函数库（如 `dom.js`、`string.js`、`date.js`、`canvas.js`），便于 Tree-Shaking 进一步缩减打包产物体积；
  - 引入 TypeScript 对核心页面契约（`PageConfig`、`TabItem`、`ControlItem`）进行静态类型约束，配合 IDE 的智能自动补全，能进一步避免配置声明时字段名的拼写疏漏。
